# 自托管 PkuHole Observer

PkuHoleStudio 的 Observer 集成只连接你自己部署的 HTTPS 服务，不再调用第三方热点统计接口。Observer 在服务器上长期运行；Studio 和你的电脑可以随时关闭，重新打开后通过持久化游标补同步期间发生的删除与恢复事件。

## 首次配置

1. 按 `PkuHoleObserver` 仓库中的 `README.md` 在服务器部署服务，妥善保存生成的 API Token。
2. 打开 Studio Web 的“设置 → Observer”。
3. 填写 Observer 的 HTTPS 地址和 API Token，先执行“测试连接”，并核对提示中的服务版本和 commit 是否与准备部署的 Release 一致。Token 保存后只显示“已配置”，API 不会回显原值；旧版 Observer 没有构建身份字段时仍可连接，但不会显示版本。
4. 启用 Observer，并按需启用“启动时同步”“定时同步”和“导出前同步”。
5. 查看状态中的登录、扫描时间、分页覆盖、队列深度、流量保护和基线状态。默认需要连续 12 小时覆盖完整的热点扫描来建立安全基线；中途长时间断档会重新累计。基线完成前只保存内容，不根据列表缺失确认删除。

之后 Observer 会自行扫描。一个已观察到的洞只有在健康且覆盖完整的扫描中消失，并且详情接口间隔一段时间连续两次明确返回不可访问、同时至少一个近期对照洞仍能读取，才会生成删除事件和单洞 Archive v2 快照。异常空列表、网络故障、限流、登录失效或分页不足不会被当成删除。

## 日常使用

- “总览”的热点优先来自 Observer；Observer 暂时不可用时，Studio 会使用最近一次 Observer 缓存或本机在线时间线近似排序，并明确标记来源与陈旧状态。
- “删除归档”展示已经同步到本地的确认不可访问和恢复记录。点开记录读取的是导入 Studio 的本地快照，因此 Observer 暂时离线时仍可查看。
- 手动同步会从上次事件游标继续；Observer 数据库恢复或重建导致实例 ID 改变时，Studio 会自动从新实例的游标 0 重放并去重。
- 普通会话过期由 Observer 使用服务器 Secret 中的账号密码自动重登。IAAA 与 Treehole 二次认证都可能要求短信或 OTP；设置页会显示真实阶段和验证码类型，短信才提供重发按钮。服务器配置了对应 TOTP Secret 时可自动提交动态口令，否则手动提交一次验证码后扫描恢复。本地 Secret/Cookie 配置错误会明确显示为“认证配置异常”，不会误报成密码错误。
- Observer 收到 429、带恢复时间的 503，或者连续遇到 5xx、网络/协议异常时，会统一暂停所有上游请求。保护期结束后只放行一个探针，探针成功才恢复正常流量，失败则立即重新保护。设置页将“全局退避/熔断”与“登录失败”分别展示，并给出预计恢复时间和连续失败计数；保护窗口内“重新登录”会禁用，已同步到本机的数据仍然可用。

请求基础间隔、随机抖动、每主机连接数和熔断阈值属于服务器运行参数，应在 Observer 的 `.env`/Compose 中调整。若频繁出现限流，应增加请求间隔，而不是增加 worker、连接数或反复手动扫描。

## 导出行为

开启“导出前同步”后，Studio 在创建导出快照前先拉取 Observer 的最新事件。同步失败时不会悄悄导出旧数据：界面会要求重试，或由你明确选择“使用当前本地数据继续导出”。导出本身始终读取 Studio 本地数据库，不会把一个长时间任务绑定到远端连接。

## 持续运行边界

需要长期在线的是服务器上的 Observer 容器，而不是本地 Studio。只要服务器、域名、HTTPS、数据卷和 IAAA 凭据仍可用，Observer 会在重启后恢复队列、自动重登并继续使用原实例 ID 和同步事件序列。它无法恢复部署前就已经删除且从未观察到的内容；删除过快时，评论或媒体也可能只能保存为 `partial`。
