# PkuHoleStudio v0.1.0-alpha.4

这是一次面向“在线浏览 + 本地研究 + 自托管观察”的预览版本。alpha.4 把此前散落的功能整理成两个明确工作区，加入研究项目和证据化 AI 工作流，并完成 Studio 侧的自托管 Observer 接入。同时，归档协议升级到中立的 PkuHole Archive Contract 2.1.0，Web 增加经典树洞和 GitHub 布局预设。

> 本版仍是 alpha 预览版。升级前请备份资料目录与数据库；Observer 的生产部署和长时间真实流量基线仍需在独立服务器上完成验收。

## 本版重点

### 两个工作区与研究流程

- “在线树洞”集中处理登录、时间线、互动、通知和校园信息；“本地研究”集中处理资料库、搜索、项目、AI、导入导出和维护任务。
- 工作区和最近访问位置会保存，刷新或重新打开后可以恢复；全局任务反馈不会因为切换页面而丢失。
- 研究项目可以组织帖子、评论和研究记录，批量选中后可进入证据化 AI 报告流程。
- AI 报告保存 PID/CID、来源摘录和检索轨迹，便于从结论回到本地证据；OpenAI-compatible Provider 继续采用显式配置和 API key 只写不回显策略。

### 自托管 Observer

- Studio 只连接你自己部署的 HTTPS Observer，不调用第三方热点统计服务。
- 支持 Token 配置、连接测试、认证挑战、短信/OTP 续登、持久化事件游标、热点缓存、删除/恢复记录和单洞 Archive v2 快照同步。
- 删除确认不是根据一次列表缺失直接判断：需要健康且覆盖完整的扫描、间隔进行的详情复核，以及近期对照洞仍可读取。网络故障、限流、登录失效、分页不足和异常空列表不会生成删除事件。
- “导出前同步”失败时不会静默导出旧数据，必须重试或明确确认使用当前本地数据。
- Studio 本机不需要长期运行；需要长期在线的是服务器上的 Observer、数据库卷和 HTTPS 入口。完整配置和运行边界见 [自托管 Observer 使用说明](../self-hosted-observer.md)。

### Archive Contract 2.1

- Studio 原生读写 PkuHole Archive Contract 2.1.0，并公开 schema、扩展和归档大小能力供发送端协商。
- 新归档使用 ZIP STORE 基线，读取端继续接受旧 DEFLATE；Studio 与 Toolkit 使用共享 fixtures 和真实 ZIP 黄金包验证双向兼容。
- `studioSources` 使用稳定字段并限制长度、去重、过滤归档哈希链，避免反复导入导出导致来源历史无限增长。
- Toolkit 本地桥接支持可撤销设备信任和逐次签名票据；票据绑定文件名、大小和 SHA-256，Studio 仍会在预检后要求用户确认。

### Web 布局与质量基线

- 保留 Studio 默认布局，并增加经典树洞和 GitHub 两套预设。
- 经典/GitHub 预设覆盖明暗主题、桌面与窄屏布局、键盘路径和主要详情场景。
- Windows Chromium 视觉基线与发布 CI 平台保持一致，减少跨平台字体与渲染差异产生的无效截图变化。

## Windows 安装

1. 下载 `treehole-windows-amd64.zip` 和 `SHA256SUMS.txt`。
2. 在 PowerShell 中计算压缩包哈希并与清单比较：

   ```powershell
   (Get-FileHash .\treehole-windows-amd64.zip -Algorithm SHA256).Hash
   Get-Content .\SHA256SUMS.txt
   ```

3. 解压到独立目录，例如 `D:\PkuHoleStudio`。
4. 启动 Web：

   ```powershell
   .\treehole-windows-amd64.exe web
   ```

5. 浏览器默认打开 `http://127.0.0.1:8080`。默认资料位于程序工作目录的 `data` 文件夹。

默认 TUI 启动方式：

```powershell
.\treehole-windows-amd64.exe
```

如需 TUI 与 Web 明确共用资料，请始终传入相同的资料目录和数据库路径：

```powershell
.\treehole-windows-amd64.exe --data-dir D:\PkuHoleStudio\profile --db-path D:\PkuHoleStudio\profile\studio.db
.\treehole-windows-amd64.exe --data-dir D:\PkuHoleStudio\profile --db-path D:\PkuHoleStudio\profile\studio.db web
```

## 升级与回滚准备

- 退出正在运行的 TUI/Web，并完整备份 `data` 目录和 SQLite 数据库。
- alpha.4 会自动执行数据库迁移；首次启动后检查资料库、任务中心、Provider 配置和 Observer 状态。
- 不要把 `cookies.json`、数据库、真实归档、API key、Observer Token、密码或验证码提交到仓库或发送给他人。
- 如需回退程序版本，应同时恢复升级前的数据库备份，不要让旧程序直接写入已迁移的数据库。

## 发布验证范围

发布候选至少应通过以下门槛：

- `go test -tags sqlite_fts5 ./...`
- `go vet -tags sqlite_fts5 ./...`
- `go build -tags sqlite_fts5 ./cmd`
- `cd web && npm test`
- `cd web && npm run build`
- `cd web && npm run e2e`
- Archive Contract 共享 fixtures、Studio/Toolkit 双向黄金包和工作区兼容检查
- Windows 产物启动、版本号、SHA-256 清单和 Web/TUI 共用资料目录冒烟测试

## 已知限制与后续验收

- Observer 是独立服务，不包含在 Studio Windows 压缩包中。alpha.4 完成的是 Studio 侧客户端和同步闭环；正式使用前仍需部署 Observer，并观察至少连续 12 小时的完整扫描基线、重启恢复、认证挑战、限流退避和删除/恢复事件。
- Observer 无法恢复部署前已经删除且从未观察到的内容；删除过快时，评论或媒体快照可能标记为 `partial`。
- 视觉回归当前固定为 Windows Chromium；Firefox、WebKit、系统读屏器和更多操作系统仍需单独扩展兼容矩阵。
- AI 输出取决于用户配置的第三方或本地 Provider。证据链接用于帮助核查，不代表模型结论必然正确。
- 本地 Windows 环境若启用应用程序控制，临时生成的 Go 测试可执行文件可能被系统策略阻止；发布标签必须以 CI 中完整通过的 Go 测试为准。

## 安全、合规与许可状态

- Web 默认仅绑定 `127.0.0.1`；不要直接暴露到公网。
- Observer 只应在你拥有合法授权的账号、服务器和使用场景中部署，并遵守适用的服务规则、隐私要求和请求频率限制。
- 本仓库及其上游目前均未提供明确的开源许可证。alpha.4 不改变这一状态，也不自动授予复制、修改、再发布或商用权利；正式公开分发前需要完成代码来源和许可审计。第三方依赖继续适用各自许可证。
