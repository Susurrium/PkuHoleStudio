# PkuHoleStudio 经典树洞 UI 规格

状态：设计基线（2026-07-15）
适用范围：Web 前端第二套官方 UI 预设
内部标识：`classic`
用户可见名称：`经典树洞`

## 1. 目标与边界

经典树洞不是给现有界面更换颜色，而是一套建立在相同业务能力之上的独立布局预设。它要恢复原版树洞的阅读节奏和空间记忆，同时完整承载 PkuHoleStudio 已有的本地资料、在线会话、同步、AI、任务、通知、导入导出、维护、日志和校园信息功能。

核心目标：

1. 还原顶部双层导航、固定背景、主洞纵向排列、回复横向展开和右侧详情抽屉。
2. 列表、搜索、详情和回复保持在同一视觉上下文，不因进入详情丢失列表位置。
3. 当前 `studio` UI 继续作为默认预设，两套 UI 共用数据、权限和副作用边界。
4. 任何 UI 切换都不触发同步、发布、回复、点赞、关注或已读操作。
5. 新增功能使用分层入口和详情页签安置，不挤满经典工具栏。

不在本阶段复制原站源码、品牌标志或未经授权的背景素材。实现采用独立代码和自有视觉资产，复刻的是信息架构与操作语法。

## 2. UI 预设模型

### 2.1 三层能力

| 层级 | 能改变什么 | 适用对象 | 安全边界 |
| --- | --- | --- | --- |
| 视觉主题 | 颜色、字体、圆角、阴影、背景和密度 | 官方及未来用户主题 | 仅声明式令牌和静态资源 |
| 布局预设 | 导航、页面结构、抽屉、列表和响应式策略 | 官方内置 UI | 随应用编译并经过测试 |
| 功能插件 | 新路由、新数据源和新操作 | 未来高级扩展 | 单独设计权限、签名与沙箱，不与主题包混用 |

`studio` 和 `classic` 都是可信布局预设。未来开放给用户的第一版主题格式只包含视觉主题；用户自定义完整布局必须等插件权限模型成熟后再开放。

### 2.2 共享层

以下内容不得在两套 UI 中各实现一份业务规则：

- API 调用、React Query 缓存键和错误解释。
- 在线会话与读写权限判断。
- 帖子、评论、媒体、通知、任务、标签、笔记和引用关系模型。
- 发布、回复、点赞、关注、同步、导入导出等副作用。
- URL 查询参数语义和可深链接状态。
- 确认对话框、通知反馈和敏感数据策略。

布局预设只决定这些能力放在哪里、如何组合以及如何响应不同屏幕。

## 3. 信息架构

### 3.1 顶部产品导航

经典模式保留原版居中的紧凑导航节奏，但使用 Studio 自己的模块：

| 入口 | 路由 | 职责 |
| --- | --- | --- |
| Studio | `/` | 总览与工作状态 |
| 树洞 | `/posts?source=live` | 在线时间线和经典阅读主场景 |
| 资料 | `/posts?source=local` | 本地资料库、标签和笔记 |
| AI 研究 | `/ai` | 基于资料的研究工作台 |
| 工具 | 弹层菜单 | 任务、同步、导入导出、维护、日志、设置 |

校园课表与成绩进入“工具”菜单中的独立入口，避免把所有模块平铺到顶部。

### 3.2 树洞吸顶工具栏

桌面顺序：

1. `最新`：清除关注和分组范围，保留当前来源。
2. `关注`：在线来源时请求关注列表；本地来源时显示本地收藏/关注资料。
3. `来源`：在线树洞 / 本地资料。
4. 搜索输入：支持正文关键词和 `#PID`。
5. 标签筛选：在线标签或本地标签。
6. 分组筛选：关注分组；后端未支持时不伪造数据。
7. 搜索按钮。
8. 消息。
9. 账户与设置。
10. 发表：仅在线会话具备写权限时启用。

工具栏到达视口顶部后吸附；顶部产品导航和标题区随页面滚动离开。

### 3.3 Studio 扩展入口

| 功能 | 经典模式位置 |
| --- | --- |
| 后台任务 | 工具栏右侧状态图标 + 工具菜单 |
| 同步 | 工具菜单中的“同步中心” |
| 导入导出 | 工具菜单中的“资料迁移” |
| 资料库维护 | 工具菜单高级区 |
| 运行日志 | 工具菜单高级区 |
| AI 分析 | 洞详情中的 `AI` 页签和顶部 AI 入口 |
| 本地标签、笔记 | 洞详情中的 `个人资料` 页签 |
| 引用关系 | 洞详情中的 `引用` 页签 |
| 课表、成绩 | 工具菜单中的“校园”入口 |
| UI 切换 | 账户菜单和工具菜单底部 |

## 4. 页面与组件规格

### 4.1 经典外壳 `ClassicShell`

- 页面背景固定，不随内容滚动。
- 背景由可替换资源与渐变遮罩组成；默认使用项目自有的星空风格资产。
- 顶部导航、标题分隔线和页面正文处于正常文档流。
- 非树洞模块在半透明浅色工作区中显示现有页面，不强行改造成帖子卡片。
- 桌面保留横向空间；移动端取消背景上的横向回复链。

### 4.2 线程列表 `ClassicPostsPage`

每一行是一个线程：

- 根帖卡片桌面基准宽度 600px，最小宽度 480px。
- 回复预览卡片基准宽度 290px，按时间从左向右。
- 根帖高度由正文和媒体决定；回复卡片分别自适应内容高度。
- 整个根帖卡片可点击，链接、按钮、选择文本和媒体操作除外。
- 鼠标悬停和键盘聚焦时显示左侧 `»` 导向标记。
- 新近内容使用左上黄色节点和细竖线形成时间线。
- 根帖为白色；回复按线程内身份稳定映射到低饱和色板。
- 引用回复在正文前显示灰色引用条。
- 超出视口的回复链允许横向滚动，并提供渐隐提示；页面本身不产生不可控的横向滚动。

数据降级：

- 在线列表存在 `comment_list` 时直接显示回复预览。
- 本地列表没有评论预览时只显示根帖，不为屏幕内每一行自动请求详情。
- 搜索命中的评论可作为回复预览展示，并明确标记为“命中评论”。
- 媒体未获得可用 URL 时显示图片状态，不生成错误请求。

### 4.3 详情抽屉 `ClassicPostDetailDrawer`

桌面：

- 从右侧覆盖约 72% 视口，最小保留 320px 的背景列表。
- 背景增加半透明遮罩；关闭后恢复原滚动位置。
- 抽屉内部独立滚动，回复编辑器固定在底部。
- 标题栏显示 `树洞 #PID`、关闭按钮和关注分组。
- 操作栏包括刷新、正序/逆序、关注、点赞、保存到本地和更多操作。
- 没有后端能力的操作必须隐藏或标记不可用，不得伪造成功。

移动端：

- 详情占满屏幕，不保留左侧列表。
- 顶部固定返回栏，底部安全区内固定回复编辑器。
- 返回后通过 URL 和会话存储恢复列表位置。

详情内容：

1. `评论`：根帖、完整评论、分页加载和引用回复。
2. `个人资料`：本地标签、帖子笔记和评论笔记。
3. `引用`：引用列表和关系图。
4. `AI`：以当前洞为范围启动研究或打开关联研究。

在线详情中的副作用继续使用现有服务；本地详情隐藏在线发布动作。

### 4.4 搜索

流程：

1. 用户在吸顶工具栏直接输入，不跳转独立搜索页。
2. 纯数字或 `#数字` 打开对应详情抽屉。
3. 普通关键词写入 `q` 查询参数并刷新当前列表。
4. 标签、分组、来源和关键词共同进入可复制 URL。
5. 搜索期间保留旧结果并显示轻量加载状态，避免整页闪白。
6. 无结果在列表起始处显示清除筛选操作。
7. 返回详情前状态时恢复查询条件和滚动位置。

### 4.5 发表与回复

发表使用右侧抽屉：标签选择、正文、媒体预览、字符计数、协议提示和发表按钮。回复使用详情底部编辑器。

安全规则：

- 未登录时显示前往同步中心，不显示可提交的假表单。
- 发布和回复只有显式点击最终按钮才执行。
- 上传失败保留正文和其余文件。
- 提交中禁止重复提交。
- 成功后清空草稿并刷新相关查询；失败不清空。
- 页面关闭前存在草稿时给出本地提示；首版可先使用会话存储。

### 4.6 消息、账户与工具

- 消息：右侧抽屉，交互通知和系统通知分栏；单条点击再标记已读。
- 账户：会话状态、登录/退出、视觉设置、屏蔽词和 UI 切换。
- 工具：轻量弹层只负责导航；复杂功能仍进入现有完整页面。
- 任务：顶部图标显示运行中/失败数量，展开后只显示最近任务摘要。

## 5. 状态模型与 URL

### 5.1 本地持久化

| 键 | 内容 |
| --- | --- |
| `pkustudio:layout-preset` | `studio` / `classic` |
| `pkustudio:classic:background` | 背景标识 |
| `pkustudio:classic:color-mode` | `system` / `light` / `dark` |
| `studio:list-scroll:<url>` | 列表滚动位置，会话级 |

UI 预设切换只写前端本地存储，不写服务端配置。

### 5.2 查询参数

| 参数 | 说明 |
| --- | --- |
| `source=live|local` | 内容来源 |
| `q=` | 搜索词 |
| `followed=true` | 关注范围 |
| `label=` | 在线标签/分组 |
| `tag=` | 本地标签 ID |
| `media=true|false` | 媒体筛选 |
| `sort=` | 本地排序 |
| `return_to=` | 关闭详情后的完整列表 URL |
| `comment_cursor=` | 评论分页恢复点 |

详情路由继续使用 `/posts/:pid`，经典布局把它表现为抽屉，现代布局表现为完整页面。

## 6. 视觉系统

经典模式使用单独的 CSS 作用域，不覆盖现代 UI 的通用令牌。

初始令牌：

- 背景深蓝：`#173b68`
- 背景青蓝：`#1d7f9a`
- 卡片白：`rgba(255,255,255,.94)`
- 遮罩：`rgba(16,25,39,.48)`
- 文本：`#171717`
- 次要文本：`#60656d`
- 节点黄：`#ffc85a`
- 链接蓝：`#285bc5`
- 身份色：绿、粉、蓝、黄、紫、青的低饱和变体

排版以系统中文无衬线字体为主，正文桌面 14–15px，元信息 11–12px。经典预设保留紧凑密度，但所有可点击目标至少 32px，移动端至少 44px。

## 7. 响应式与可访问性

断点策略：

- `>= 1200px`：完整横向回复链和 72% 详情抽屉。
- `768–1199px`：根帖 480px，回复 260px，详情宽度约 82%。
- `< 768px`：单列卡片；回复预览变为根帖下方最多两条；详情全屏；底部主导航。

可访问性要求：

- 根帖卡片具有链接语义、键盘 Enter 打开和清晰焦点框。
- 抽屉使用对话框语义，打开时聚焦标题或关闭按钮，Escape 关闭，焦点不泄漏到背景。
- 图标按钮均有中文可访问名称。
- 颜色不是身份、选中、错误或未读状态的唯一表达。
- 尊重 `prefers-reduced-motion`，关闭抽屉和背景动画。
- 提供跳到列表、跳到评论和跳到编辑器的隐藏链接。

## 8. 性能与故障策略

- 首屏不因经典背景阻塞帖子请求。
- 背景资源提供 WebP/AVIF 和纯 CSS 降级。
- 列表不做 N+1 详情请求；只使用列表携带的回复预览。
- 抽屉按路由懒加载，打开后再请求完整详情。
- 图片使用懒加载、尺寸占位和最大显示高度。
- React Query 缓存键与现代 UI 一致，切换 UI 不重复下载已有数据。
- 搜索和筛选保留上一页数据，加载失败可原位重试。
- 离线或会话过期不清空本地列表。

## 9. 实施阶段

### 阶段 1：预设基础设施

- 增加 `studio` / `classic` 注册、持久化和即时切换。
- 新建经典外壳和作用域样式。
- 所有现有路由在经典外壳下仍可访问。
- 增加切换测试和回退测试。

### 阶段 2：经典列表

- 实现双层顶部区域、吸顶工具栏和背景。
- 接入本地/在线列表、搜索、标签、关注和分页。
- 实现整卡点击、横向回复链、引用条和媒体状态。

### 阶段 3：经典详情

- 详情抽屉、遮罩、关闭和滚动恢复。
- 评论分页、正逆序、刷新、点赞、关注、引用回复和媒体。
- 移动端全屏详情。

### 阶段 4：原版功能抽屉

- 发表、消息和账户抽屉。
- 权限、确认、草稿和错误状态。
- 关注分组与屏蔽词在后端能力允许时接入。

### 阶段 5：Studio 扩展能力

- 个人资料、引用和 AI 页签。
- 任务摘要和工具菜单。
- 现有完整工具页面的经典容器适配。

### 阶段 6：质量收口

- 手机、平板、超宽屏和缩放测试。
- 键盘、读屏、减弱动画和对比度测试。
- 与录屏关键帧进行视觉回归。
- 构建、单元测试、端到端测试和 Go 测试。

## 10. 验收清单

1. 默认仍进入现代 `studio` UI。
2. 切换经典 UI 后刷新页面仍保持选择。
3. 随时可以切回现代 UI，路由和数据不丢失。
4. 经典模式点击根帖任意非交互区域均打开详情。
5. 详情关闭后搜索条件和列表位置保持不变。
6. 在线未登录、只读和可写三种权限状态显示正确。
7. 搜索、标签、关注、来源和分页可组合使用。
8. 回复身份颜色在同一线程中稳定，引用条可辨识。
9. 发布、回复、点赞、关注和已读不会由页面打开自动触发。
10. 经典模式的 Studio 新功能不挤占主要阅读空间。
11. 360px 宽度无页面级横向溢出，桌面横向回复链可单独滚动。
12. Escape、浏览器后退、关闭按钮和移动端返回行为一致。

## 11. 未来用户主题格式

第一版用户主题包建议结构：

```text
theme-name/
├── theme.json
├── tokens.json
├── preview.webp
└── assets/
    ├── background.webp
    └── optional-textures.webp
```

`theme.json` 只声明名称、作者、兼容版本、目标布局预设和资源清单。`tokens.json` 只接受白名单视觉令牌；禁止 JavaScript、远程脚本、任意 HTML、跨域字体和可执行 SVG。安装前校验大小、MIME、哈希和路径，运行时使用 CSS 变量与受控资源 URL。完整用户布局插件另立规范，不借主题包绕过权限边界。
