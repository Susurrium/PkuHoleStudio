# 树洞内容更新

已保存树洞打开详情后，先显示本地内容；在线会话可用时，后台获取正文、统计及新增评论，并合并到本地。新增评论跨多页时会继续读取，整批读取成功后再提交，失败时保留原有内容。未保存的在线洞保持浏览行为，只有主动保存才进入资料库。

详情页的“完整更新本地内容”创建持久化任务，重新读取全部评论，并按照已有保存任务中的图片选项补全缺失媒体。任务完成后可以再次更新。列表选择多个洞后，可使用“保存或更新所选树洞”。标签、笔记、项目关联及历史评论保留；真实关注、点赞和评论数量允许下降。历史删除快照不自动改写。

## 持续更新

此功能默认关闭。在详情页启用“持续更新此洞”，或在“登录与保存 → 持续更新关注洞”配置已经保存、当前账号仍关注的 PID。

| 限制 | 行为 |
| --- | --- |
| 目标数量 | 每账号最多 20 个，超限拒绝保存 |
| 周期 | 30、60、120 分钟，默认 60 分钟 |
| 单轮请求预算 | 最多 100 次，分页、失败和图片请求均计入 |
| 请求并发 | 全部树洞请求共用一个执行位置，响应体读取结束后释放 |
| 启动间隔 | 至少 1 秒；网络错误、429、5xx 后统一退避，尊重 Retry-After |
| 运行边界 | 关闭浏览器后继续；退出程序或关闭电脑后停止 |

每轮开始前通过数据库原子领取并持久化下轮计划，重启、反复开关或多个 Web 进程不能提前开始同一轮。TUI 不启动后台调度。目标按顺序轮转；预算用完时保留评论分页和媒体补全阶段，下一轮继续。用户主动更新优先于后续后台请求。同 PID 的活动更新合并，完整更新会等待正在执行的增量读取结束。修改设置会停止当前进程正在执行的轮次；旧进度不能覆盖已经变更的设置。

确认取消关注后移出更新范围，已有资料保留。每轮重新检查关注状态；检查失败时保留目标和错误，不推断为取消关注。配置按会话中的稳定账号标识分别保存，请求发送和内容提交前核对账号；切换账号后旧轮次停止，原账号计划保留。普通资料库不进行全量定时扫描。

## 接口与存储

- `GET /api/v1/post-updates`：读取当前账号设置、进度、错误及本进程内容修订号。
- `PUT /api/v1/post-updates`：提交 `enabled`、`interval_minutes`、`pids`，服务端验证数量、周期、本地存在性和线上关注关系。
- `POST /api/v1/posts/:pid/refresh`：`{"full":false}` 更新已保存内容中的正文及新增评论；`{"full":true}` 创建完整更新任务。
- `/api/v1/capabilities` 的 `post_updates` 表示上述能力是否可用。

数据库迁移 14 增加 `post_update_schedules`，每账号一条调度记录。目标分页状态仅记录在启用的目标集合中；普通历史树洞不新增逐条新鲜度记录。完整更新沿用现有任务、评论和媒体表。

浏览器定期读取本机内容修订号，后台提交后使相关查询失效并重新获取；完整更新、导入等任务的终态变化也会触发页面数据刷新。

## 验证

回归测试覆盖多页新增评论、请求失败后重试、个人元数据保留、重复完整更新、数量和频率拒绝、分页续传、重启、取消关注、账号切换和历史快照保护。客户端测试通过本机 HTTP 服务验证真实请求次数、响应体互斥、启动间隔、取消和 Retry-After；应用接口测试使用独立 SQLite 数据库及受控上游适配器。三个 Web 界面的自动刷新和再次更新由前端测试覆盖。

周期性读取无法保证捕获两个周期之间出现又消失的内容。上游评论分页没有稳定快照标识，读取期间线上内容变化可能影响分页；手动完整更新用于重新核对历史评论。上述数量和频率属于应用限制，不代表上游服务对相应流量的承诺。
